## Failures reproduced and corrected

1. [Run 35382203039](https://github.com/yashthakur2008/ARGUS/actions/runs/35382203039) failed the backup failure-injection case. A trailing slash in the runner's temporary directory produced a double slash in the fixture path, while the packager normalized its root. An exact comparison in the fake `mv` therefore missed the intended injection. Local reproduction failed the same assertion. Commit `19b2586` canonicalizes the owned fixture root and adds a CI path matrix. That matrix additionally reproduced unquoted mocked command paths failing on whitespace, fixed with a quoted runtime `$FIXTURE` reference. Production packaging and preservation assertions were not changed.

2. [Run 35384084769](https://github.com/yashthakur2008/ARGUS/actions/runs/35384084769) passed path checks, then failed the WAL migration test with `SQLITE_BUSY`. A direct Swift Testing helper run with `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1` reproduced the failure: the blocking opener occupied the executor needed by the test's timed writer rollback. Commit `a849b63` moves that test's blocking opener to a dispatch worker. The same constrained test passed afterward. Production retry budgets, migration assertions and the exhaustion test remain unchanged. This fixes self-induced starvation, not arbitrary scheduling delays under every possible load.

The constrained environment must be applied to the test helper, not the SwiftPM driver. Applying it to the driver stalled before tests and was stopped; that experiment is not product failure evidence.

Independent review was source-only. Local and hosted execution were performed separately by the coordinator. Raw local logs are retained in the agent scratch directory `argus-ci-improvement-20260918`; hosted logs are linked above.

## Scope and reassessment

This closes the clean Xcode development-build verification gap. It does not establish distribution signing, notarization, sandbox isolation, actual notification delivery, native accessibility, or live microphone/provider behavior. See the [commercial readiness checkpoint](2026-09-18-commercial-readiness.md).

Further asynchronous mutation work requires explicit ownership of shared error state and additional overlap regressions. Distribution and native acceptance require separate authorized workflows. Those are not low-risk follow-ons to these two concrete CI failures, so this batch stops without broader production changes.
